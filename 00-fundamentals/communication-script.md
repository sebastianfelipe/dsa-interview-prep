# Communication Script

Use these phrases so your thinking is audible and structured.

## Opening

> "Let me restate the problem to confirm… Inputs are … Output should be … Constraints suggest we need about O(…) time."

## Brute force

> "The naive approach is … which is O(…). The bottleneck is …"

## Pivot to optimal

> "We can avoid recomputing X by storing Y in a hash map / expanding a window / binary searching the answer."

## Confirm before coding

> "Plan: I'll use [pattern]. Time O(…), space O(…). Does that sound good to proceed?"

## During code

> "I'm creating a dummy head so edge cases for empty/single node are cleaner."
> "Left and right define an inclusive window that always satisfies the invariant…"

## Dry-run

> "On input […]: initially left=0, right=0, … After processing 3, window becomes … Final answer …"

## Bug found mid-interview

> "I see an off-by-one when right exits the array — I'll adjust the loop bound."

## Key Extract

Narrate **why**, not just what. Interviewers hire the reasoning.
